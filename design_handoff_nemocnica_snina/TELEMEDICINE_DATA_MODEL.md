# Telemedicine Data Model — Nemocnica Snina

Extends `DATA_MODEL.md`. All conventions from that document apply (bilingual `loc` fields, slug `id`, etc.). Patient data is never stored in our DB — video session identity and post-call summaries are written to the HIS/FHIR layer via the async queue.

---

## New tables (PostgreSQL, managed by the API)

### telehealth_sessions
One row per booked video consultation. Created when a booking with `mode=telehealth` is confirmed; updated as the session progresses.

| column | type | notes |
|---|---|---|
| id | uuid PK | stable session identifier; used in the room URL `/konzultacia/[id]` |
| booking_id | uuid FK → bookings | the underlying appointment booking |
| clinic_id | text FK → clinics | |
| physician_id | text FK → physicians | |
| patient_token | text | opaque token linking to the eID-verified patient context; **not** an RČ or personal identifier in our DB |
| scheduled_at | timestamptz | |
| status | enum | `scheduled` · `waiting` · `active` · `ended` · `cancelled` · `no_show` |
| started_at | timestamptz? | when physician admitted the patient |
| ended_at | timestamptz? | |
| duration_seconds | int? | computed on end |
| video_provider | text | e.g. `livekit`; identifies the signaling provider |
| provider_room_id | text | room name/ID in the video provider |
| patient_join_token | text | short-lived JWT for the patient; issued on join, expires 15 min after `scheduled_at` |
| physician_join_token | text | short-lived JWT for the physician |
| tokens_issued_at | timestamptz | |
| intake_submitted | bool | patient completed the pre-call intake form |
| his_synced | bool | post-call summary pushed to HIS via queue |
| created_at | timestamptz | |
| updated_at | timestamptz | |

### telehealth_intake
Pre-consultation questionnaire filled by the patient (day before or at the waiting room).

| column | type | notes |
|---|---|---|
| id | uuid PK | |
| session_id | uuid FK → telehealth_sessions | |
| reason | text | reason for visit (free text) |
| current_medications | text | free text list |
| symptoms | text | current symptoms |
| vitals_note | text? | optional self-reported vitals (BP, weight, blood glucose) |
| submitted_at | timestamptz | |

> **No diagnosis or clinical assessment** is stored in the intake table. Those are physician notes and go to HIS via the FHIR Encounter resource.

### telehealth_summaries
Post-call summary generated by the physician (or pre-populated from HIS on sync). Cached here for portal display; the authoritative copy is in HIS.

| column | type | notes |
|---|---|---|
| id | uuid PK | |
| session_id | uuid FK → telehealth_sessions | |
| clinical_note | text | physician's free-text assessment |
| follow_up_recommendation | loc | bilingual follow-up text |
| prescription_issued | bool | whether an e-prescription was issued this session |
| prescription_ref | text? | reference ID in the HIS e-prescription system |
| pdf_path | text? | server-side path to the generated summary PDF (gated by step-up 2FA on download) |
| his_encounter_id | text? | FHIR Encounter.id written to HIS |
| created_at | timestamptz | |

### telehealth_sessions — status transition constraint
Enforce legal state transitions at the DB layer (CHECK constraint or trigger) in addition to the application layer:
```
Allowed: scheduled→waiting, waiting→active, active→ended, any→cancelled, scheduled→no_show
Forbidden: ended→active, ended→waiting, no_show→active, cancelled→any
```
Illegal transitions must raise a DB-level exception so that a bug in the application layer cannot corrupt session state.

### telehealth_audit_log_view
Not a physical table — a logical view over `audit_log` filtered to `entity_type IN ('telehealth_session','telehealth_summary')`. Every state transition, join event, provider token issuance, intake submission, and summary download writes an immutable `audit_log` entry (same append-only table, same `INSERT+SELECT`-only app role).

## Retention — critical distinction (Act 576/2004 §24)

| Data | Location | Retention | Authority |
|---|---|---|---|
| `telehealth_sessions` | Our PostgreSQL | 5 years | Operational metadata only — NOT the medical record |
| `telehealth_intake` | Our PostgreSQL | 5 years (with session) | Pre-call questionnaire — clinical detail excluded |
| `telehealth_summaries` | Our PostgreSQL | 5 years; `pdf_path` files purged after 7 days | Portal cache only — NOT the medical record |
| FHIR `Encounter` (post-call) | HIS | **20 years** (Act 576/2004 §24) | **Authoritative medical record** |
| FHIR `MedicationRequest` | HIS + NCZI eZdravie | 20 years | Prescription record; NCZI eZdravie is the legal prescription |

**Critical rule:** `telehealth_summaries` rows where `his_synced = false` must **never** be eligible for purge. The 5-year / 7-day purge schedules only apply after `his_synced = true` is confirmed. The HIS vendor must contractually confirm 20-year retention of FHIR Encounter records for teleconsultations (add to `LAUNCH_CHECKLIST.md §L7`).

## FHIR R4 mapping

| Post-call event | FHIR resource | Notes |
|---|---|---|
| Session completed | `Encounter` | `status: finished`; `class: VR` (virtual); `participant[]` → physician; `period` → start/end |
| Clinical note | `Encounter.text` (narrative) + `ClinicalImpression` | physician's assessment text |
| e-Prescription | `MedicationRequest` | same resource as in-person; `requester` = physician; `identifier` includes NCZI eZdravie prescription code (`urn:oid:nczi.ezdravia`) — **eZdravie submission is the legally valid prescription** (Act 362/2011); FHIR is the HIS copy |
| Follow-up | `Appointment` (proposed) | `appointmentType = followup`; references the original Encounter |
| Lab order | `ServiceRequest` | if physician orders labs during the call |

All FHIR writes go through the existing **RabbitMQ → HIS sync agent** (see `PRODUCTION_ARCHITECTURE.md` §Integrations and `TELEMEDICINE_ARCHITECTURE.md`). Event type: `telehealth.session.ended`.

## Env var additions
See `TELEMEDICINE_CONFIG.md` for the full set. Key new secrets:
- `TELEHEALTH_PROVIDER` — video signaling vendor identifier
- `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` / `LIVEKIT_URL` (or equivalent for chosen vendor)
- `TELEHEALTH_SESSION_TTL_SECONDS` — how long a join token is valid
- `TELEHEALTH_RECORDING_ENABLED=false` — must default to `false`; enabling requires DPO sign-off

## Seed data
No telehealth sessions or intake records are seeded (patient data). Do seed:
- `clinics.telehealth = true` for the pilot set (e.g. `interne`, `fro`, `angiology`) via a Strapi content migration or the admin CMS.
- `physicians.telehealth = true` for corresponding physicians.
- A `telehealth` page singleton in `pages` with `hero.badge`, `hero.title`, `hero.subtitle` content (bilingual), so staff can edit the landing-page copy without a deploy.
